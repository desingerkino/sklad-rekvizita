# СКЛАД РЕКВИЗИТА 2.3.1

Windows-приложение для учёта кинореквизита: каталог, аренда, документы, история.
Не макет — рабочая программа с базой данных, расчётами, PDF и резервным копированием.

## Исправления после первой сборки на Windows

* Восстановление из резервной копии падало с `PermissionError [WinError 32]`:
  Windows не отдавала файл журнала `data.db-wal` сразу после закрытия базы.
  Теперь удаление идёт с повторами (15 попыток), а если файл так и остался
  занят — откладывается в сторону, и восстановление продолжается.
* `Database.close()` освобождает ссылки на закрытое соединение, чтобы файлы
  журнала не удерживались до сборки мусора.

## Что нового в версии 2.3.1

**Безопасность (главное в этом выпуске)**

* Персональные данные шифруются AES-256-GCM: паспорт, телефон, адрес, e-mail
  и примечания клиентов, контакты и банковские реквизиты продакшенов, снимки
  документов. В файле базы вместо значений лежит `enc1:…`.
* Ключ шифрования хранится отдельно от базы (`%APPDATA%\SkladRekvizita\keys`),
  на Windows запечатан DPAPI, на других системах — файл с правами 0600.
* Резервные копии шифруются целиком; незашифрованные временные копии не остаются.
* Пароли — Argon2id (если установлена библиотека) либо scrypt из стандартной
  библиотеки; старые PBKDF2-хэши автоматически обновляются при входе.
* Автоблокировка сеанса после 15 минут бездействия (настраивается).

**Интерфейс**

* Иконки перерисованы строго по утверждённому UI Kit: единая сетка 24×24,
  толщина линии 1.8, круглые концы; emoji в интерфейсе не используются.
* Единая система статусов: 🟢 В наличии · 🟠 В аренде · 🔴 Пролонгация ·
  ⚪ Открыт набор / аренда · ⚫ Аренда завершена — всегда с текстом, цвет вторичен.
* Прокрутка везде, где контента больше экрана: экраны, длинные формы, модальные
  окна, таблицы; кнопки «Сохранить» и «Отмена» закреплены и не уезжают.
* Длинные названия не ломают вёрстку: обрезка с подсказкой, фиксированная высота
  карточек, ограничение ширины колонок.

## Быстрый старт (сборка .exe)

На компьютере разработчика нужны **Python 3.11/3.12 (x64)** и, для установщика,
**[Inno Setup 6](https://jrsoftware.org/isdl.php)**. Конечному пользователю ничего этого не нужно.

```powershell
cd путь\к\SkladRekvizita
powershell -ExecutionPolicy Bypass -File build\build.ps1
```

Скрипт создаёт окружение, ставит зависимости, **прогоняет все четыре набора тестов**,
собирает `dist\SkladRekvizita\SkladRekvizita.exe` и установщик `dist\SkladRekvizita_Setup_2.3.1.exe`.

Запуск без сборки (для разработки): `python main.py`

## Где лежат данные

Рабочая база **никогда** не хранится рядом с .exe и не попадает во временные папки Windows:

```
%LOCALAPPDATA%\SkladRekvizita\
├── data.db          база (SQLite, режим WAL)
├── photos\          фотографии реквизита + миниатюры
├── documents\       PDF-документы по годам
├── backups\         резервные копии с ротацией
└── logs\app.log     технический журнал
```

Переустановка и обновление программы данные не трогают. Установщик перед обновлением
сам откладывает копию базы в `backups\before_update_….db`.

## Как работают ключевые механизмы

**Доступность и пересечение дат.** `peak_reserved()` считает заметающей прямой
максимальную одновременную занятость предмета внутри запрошенного периода. Две аренды,
не пересекающиеся между собой, не складываются — блокируется только реальный пик.
Отказ объясняется человеческим языком с перечислением мешающих аренд.

**Исторический snapshot.** При создании документа весь состав данных (склад, клиент,
паспорт, продакшен, банк, проект, позиции, суммы) сохраняется в JSON. Документ всегда
рисуется из снимка — правка карточки клиента через год старый документ не меняет.

**Даты.** Единственный источник времени — системные часы и часовой пояс Windows.
В базе — ISO-формат, на экране и в документах — `ДД.ММ.ГГГГ` и `ЧЧ:ММ`.

**14-дневные периоды.** У каждой позиции хранятся дата выдачи, номер текущего периода,
его границы и дата следующей пролонгации. `run_prolongations()` сравнивает системную дату
с концом периода и добирает недостающие периоды; повторного начисления не происходит
благодаря уникальному ключу `(позиция, тип начисления, номер периода)`.

**Роли.** Проверка выполняется в бизнес-логике перед операцией (`auth_service.require_admin`),
а не только скрытием кнопок: прямой вызов сервиса обычным пользователем отклоняется.
Пароли — PBKDF2-HMAC-SHA256, 240 000 итераций, со случайной солью.

**Поиск по фото.** Встроенный провайдер работает офлайн: dHash (структура) + гистограммы
HSV + сетка средних цветов + карта границ → вектор, косинусная близость. Внешний AI/API
подключается заменой одного класса (`EmbeddingProvider`), остальной код не меняется.

**Автосохранение.** Каждая операция — одна транзакция, которая фиксируется сразу (`isolation_level=None`,
`synchronous=FULL`, WAL). Незаконченная форма «Новая аренда» пишется черновиком
через секунду после последнего изменения и предлагается к восстановлению при
следующем запуске. Аварийное завершение проверено тестом с настоящим SIGKILL:
подтверждённые данные остаются, незавершённая транзакция откатывается целиком.

Кнопка **«Сохранить всё»** (Ctrl+S) нужна не для сохранения, а для наглядности:
она сохраняет черновик открытой формы, сводит журнал WAL в файл базы и показывает
отчёт — размер базы, количество записей по разделам и явное «несохранённых
изменений нет». В строке состояния постоянно висит отметка «✔ Все изменения
сохранены» со временем последнего изменения.

**Деньги.** Все денежные величины округляются функцией `money_round()` через `Decimal`
по правилу «половина вверх»: встроенный `round()` округляет 0.125 к чётному, что для
сумм скидок и итогов неверно.

**Конкурентный доступ.** Доступность реквизита перепроверяется внутри той же
транзакции (`BEGIN IMMEDIATE`), в которой создаётся аренда, поэтому одновременные
попытки выдать последний экземпляр не приводят к двойной выдаче.

**Резервные копии.** Онлайн-бэкап SQLite — копия снимается на работающей базе и всегда
целостна. При восстановлении текущая база сначала сохраняется как `before_restore_….db`.

**Пароли.** SMTP-пароль шифруется Windows DPAPI ключом учётной записи; в базе — только шифртекст.
